# Qualité du code et pièges Lizard

Déplacé tel quel depuis CLAUDE.md (sections « Code quality », à partir de la puce Lint, et « Mesurer > deviner (règle OBLIGATOIRE) », garde-fou local et pièges Lizard), le 2026-10-21.

## Code quality

- **Lint** : `npm run lint` (ESLint + typescript-eslint + sonarjs, config `eslint.config.js`) — `lint:fix` pour les auto-fixables. Actif en `pretest` via `lint:ci = eslint . --max-warnings 0` (verrou strict, 0 warning toléré), en complément de `lint:complexity` (Lizard CCN 8 full-repo) et `lint:deadcode` (knip). Règles `no-explicit-any`, `cognitive-complexity`, `no-duplicate-string`, `todo-tag` encore configurées en `warn` mais baseline à 0 — toute nouvelle occurrence bloque `npm test`.
- **Promesses : équivalents locaux de trois règles SonarCloud, en `error`** : `@typescript-eslint/no-floating-promises` (S9383, bug), `no-await-in-loop` (S9382), `@typescript-eslint/require-await` (S7503). Messages et lignes identiques à ceux de Sonar (mesuré : 81 issues sur 81 ; ESLint voit en plus 6 `await` en boucle que Sonar tolère).
  - Promesse lancée sans l'attendre : `void f()` **seulement si `f` gère ses erreurs** (try/catch englobant, vérifié dans son code), sinon `.catch(…)`. `$nextTick` d'Alpine : `void`, sa promesse ne peut que se résoudre (`node_modules/alpinejs/src/nextTick.js`).
  - Boucle séquentielle voulue : la raison dans un commentaire au-dessus, puis `// eslint-disable-next-line no-await-in-loop -- …` et `// NOSONAR(S9382) — …` en fin de la ligne de l'`await`, qui doit tenir sur une ligne (sortir un `.catch` ou une fonction dans une constante). Restent séquentiels : les appels TTS et OCR vers Mistral (limite de débit de la clé ; pour le quiz vocal et la dictée, `runWithMediaLedger` ne doit plus rien voir écrire après son nettoyage), les réessais, et toute boucle dont un tour dépend du précédent. Parallélisés : des appels indépendants et bornés (suppressions de fichiers, écritures temporaires, outils du chat).
  - Tests : `require-await` et `no-await-in-loop` coupés (mocks `async`, étapes enchaînées), `no-floating-promises` actif.
  - Promesses que l'API rejette sans que le code n'ait rien demandé : `document.startViewTransition` rejette `transition.ready` quand la transition est sautée (onglet masqué, autre transition) alors que la vue a déjà changé → `transition.ready.catch(…)` (`goToView`, `src/app/navigation.ts`), sinon « Unhandled rejection » (vu au release-test, onglet en arrière-plan). Vitest fait échouer le run sur tout rejet non géré : un test qui rejette `ready` sert de verrou.
- **Autres scripts utiles** : `format` / `format:check` (prettier), `test:coverage` / `test:watch` (vitest), `build` / `preview` / `start` (vite + prod), `dev:server` / `dev:web` (splits isolés du `dev` combiné).
- **Tests (Vitest 5)** : `clearMocks` vaut `true` par défaut — l'historique des mocks est effacé avant chaque test. Ne jamais asserter dans un test des appels déclenchés dans un `beforeAll` : déclencher l'action dans le test ou dans un `beforeEach` (cf. `src/main.test.ts`, `vi.resetModules()` + import dynamique). `coverage.include`/`exclude` sont résolus depuis la racine du projet (plus de correspondance partielle : `types.ts` n'exclut plus que `./types.ts`).

## Pièges Lizard et garde-fou local (section « Mesurer > deviner (règle OBLIGATOIRE) »)

Garde-fou local actuel : `npm test` déclenche `pretest` → enchaîne **`typecheck` + `lint:complexity` + `lint:ci` + `lint:deadcode`** (sortie pipeline en cas d'échec d'un seul). `lint:complexity` → `scripts/check-complexity.sh` (Lizard CCN 8 strict, scope **full-repo `-l typescript`** — toute régression bloque `npm test`). Pièges connus :
- **`pipx run lizard` prend la dernière version publiée** : une nouvelle version peut mesurer une fonction que la précédente ne voyait pas et bloquer `npm test` sans qu'aucun code n'ait changé (vécu le 2026-10-18 : Lizard 1.24.1 mesure `isSafeUrl`, `src/app/render-utils.ts`, CCN réel 11, invisible en 1.22.1). Découper la fonction, jamais épingler une ancienne version qui la masque.
- **`-l javascript` ne parse pas les `.ts` en walk-dossier** — Lizard doit être invoqué avec `-l typescript` explicitement, sinon 0 violation silencieusement.
- **`??=` pèse 2 dans le comptage Lizard** (nullish check + assignment) — à retenir lors de l'application du fix `prefer-nullish-coalescing`.
- **`function foo()` top-level consécutives agglomérées** — le parseur Lizard TS peut agglomérer des `function` déclarations consécutives en une seule fonction pour compter le CCN. Fix standard : convertir un des helpers adjacents en `const foo = (): T => { ... }` arrow — Lizard ne les agglomère pas. `export function` délimite aussi correctement. À retenir quand on ajoute un helper privé à côté d'un existant.
- **Type de retour union multi-lignes = corps non mesuré** — Lizard tronque une fonction dont le type de retour est une union écrite sur plusieurs lignes : seule la signature est mesurée (vécu : `buildGenContext`, CCN réel ≈ 15 affiché 1 ; corrigé par alias `GenContextResult` + découpage en `loadGenProject`/`resolveConsigne`/`contextErrorFor`/`assembleGenContext`). Fix : alias de type pour le retour, et découper si le vrai CCN dépasse 8.
- **Paramètre de type fonction écrit en ligne = fonction coupée** — `fn: (ctx: X) => Promise<Y>` dans une signature fait perdre le corps à Lizard (vécu : `runGeneratorAndPersist` absente, `handleGeneration` réduite à sa flèche interne ; le 2026-10-28, le `builder` de `replacePendingWithTerminal` cachait TOUTES les méthodes suivantes de `ProjectStore`, dont `pruneTracker`, `normalizeModeration` et `migrateResultsFormat`, CCN réels 10 à 11). Fix : alias (`type GeneratorFn = …`, avec le `eslint-disable-line no-unused-vars…` Codacy du fichier).
- **Flèche à corps-expression sur plusieurs lignes** (`=>` en fin de ligne, ou chaîne de `&&` qui continue) : Lizard ne compte que la première ligne (vécu : `allChecksPass`, CCN réel 9 affiché 1 → réécrit en `BODY_CHECKS.every(...)`). Mettre le corps entre accolades dès qu'il porte des branches. Un `??` dans un template literal n'est pas compté non plus.
- **Génériques explicites** — Lizard ne mesure pas une déclaration `function f<T>(…)` (`safeParseJson`, `unwrapJsonArray` absents de la sortie), et un appel générique dont l'argument est lui-même un appel (`unwrapJsonArray<Flashcard>(safeParseJson(raw))`) coupe la fonction appelante à cette ligne (vécu : tout le retry de `generateFlashcards`, `generateQuizWithRetry`… échappait au plafond). Fix : fléchée `const f = <T>(…) => {…}` pour une déclaration, annotation de la variable (`const data: Flashcard[] = unwrapJsonArray(…)`) pour un appel.
- **Paramètre par défaut contenant un appel = fonction invisible** — Lizard (`-l typescript`) ne mesure pas une fonction dont un paramètre par défaut contient un appel (`legacy = new Map()`) : elle échappe au plafond CCN 8 sans signal. Fix : constante de module (`const NO_LEGACY = new Map()` puis `legacy = NO_LEGACY`, cf. `scripts/check-models.ts`), et vérifier que la fonction apparaît dans la sortie Lizard.
- **Expression parenthésée qui commence par un appel = fonction coupée** — `const run = (tails.get(key) ?? d).then(…)` ou `const r = (f(x) + 1) * 2` : Lizard arrête la fonction englobante à cette ligne, le reste du corps n'est pas mesuré (vécu : `withKeyedLock`, 2 lignes mesurées sur 15). Sans appel dans la parenthèse (`(a ?? b).then(…)`, `(x + 1).toFixed()`), rien n'est coupé. Fix : variable intermédiaire (`const previous = tails.get(key) ?? d;` puis `previous.then(…)`), et vérifier la plage mesurée. Cas fréquent au front : `(await res.json()) as T` (vécu : `selectProject`, `refreshConsigne`, `reconcilePendings`) → `const body: unknown = await res.json();` puis `body as T`.
- **Accent grave dans une regex littérale = suite du fichier invisible** — `` /`([^`]+)`/g `` : Lizard y voit l'ouverture d'un gabarit et ne mesure plus aucune fonction jusqu'à la fin du fichier (vécu : `src/app/helpers.ts`, 57 fonctions mesurées sur 128, dont `reconcilePendings`). Fix : `\x60` dans la regex. Contrôle : la dernière fonction mesurée doit se trouver près de la fin du fichier. **Même piège avec `"` et `'`** (vécu : `src/a11y-templates.test.ts`, `/x-text="([^"]+)"/g` → un `it` mesuré sur 59 lignes, que Codacy remonte en « Method has 59 lines of code (limit is 50) ») : `\x22` / `\x27` dans la regex. Une séquence d'échappement Unicode (\u suivie de 4 chiffres hexadécimaux) écrite par un outil d'édition peut arriver convertie en caractère, apostrophe comprise (vécu : `helpers/fill-blank-validate.ts`, 0 fonction mesurée) : relire les lignes de regex sur disque et compter les fonctions mesurées.
- **`<` d'une comparaison lu comme un générique** (vécu le 2026-10-28, `src/app/auto-launch.test.ts`, remonté par Codacy en « Method reply has 133 lines ») : dans `const f = (status: number): any => { return { ok: status < 300, … } }`, Lizard prend `< 300, …` pour l'ouverture d'un type générique et ne referme plus la fonction, qui avale le reste du fichier. Fix : écrire la comparaison sans `<` (`Math.trunc(status / 100) === 2` ; pas `!(status >= 300)`, refusé par `sonarjs/no-inverted-boolean-check`), puis vérifier la plage mesurée.
- **Appel optionnel `f?.()` = méthodes suivantes invisibles** — après un `this.x?.()`, Lizard peut cesser de reconnaître les méthodes suivantes d'un objet (fabrique `createConfig`, mixin `step-by-step`) ou couper la fonction : leur code est compté dans la fonction englobante, ou pas du tout (vécu : `src/app/config.ts`, `createConfig` arrêtée à la ligne 114 et 14 fonctions mesurées sur 26 ; `handleCrossTabStorageEvent` et `startEditProfile` affichées à CCN 4 et 7 pour un CCN réel de 9). Fix : un `if` explicite (`if (this.x) this.x();`), ou une petite fonction qui porte la seule branche quand le CCN est serré (`reloadMistralVoices`, `src/app/config.ts`), puis vérifier la plage mesurée. Pas `this.x?.call(this)` : Sonar le remonte en S6676 « Unnecessary .call() » (vécu sur #83, 9 issues). Tous les `?.(` ne coupent pas (`routes/generate.ts`, `quiz-vocal.ts` : mesures identiques avec et sans) : contrôler la sortie de Lizard après en avoir ajouté un.
