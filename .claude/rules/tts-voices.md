# TTS et voix

Déplacé tel quel depuis CLAUDE.md (section « TTS (Text-to-Speech) »), le 2026-10-21.

## TTS (Text-to-Speech)
- Provider unique : Mistral Voxtral TTS (`MISTRAL_API_KEY` suffit, pas de clé supplémentaire). Le support ElevenLabs historique (hackathon) a été retiré 2026-04 faute d'intégration au niveau Mistral (voix par langue, cost tracking) — une migration one-time dans `initConfig` nettoie les `config.json` legacy (`ttsProvider`/`voices`/`eleven_*`/`mistralVoices`/`mistralVoicesSource`). Réintégration ElevenLabs envisagée plus tard au même niveau de qualité.
- `apiStatus.ttsAvailable === apiStatus.mistral` (une seule source, plus de champ `elevenlabs`).
- **Types qui exigent le TTS : source unique `TTS_DEPENDENT_AGENTS`** (`generators/auto-agents.ts` : podcast, quiz vocal, dictée — une lecture audio par mot), lue par le serveur (tri de `/generate/auto`, `TTS_AGENTS` des codes d'erreur qui en dérive) ET le navigateur. Jamais de liste `['podcast','quiz-vocal']` en dur : la dictée y manquait (bouton actif sans TTS, plan auto non filtré, échec TTS classé `internal_error`). Griser un bouton de génération avec `:disabled="ttsBlocked(type)"` + tooltip `t('gen.needsTts')` (`src/app/config.ts` : `ttsBlocked` = `usesTts(type) && !ttsReady()`, `ttsReady()` = clé d'env OU clé navigateur) ; un bouton propre à un type audio teste `!ttsReady()` (vues podcast, quiz vocal, dictée). Verrou des gabarits : `src/app/config.test.ts`.
- **Voix par langue** : `resolveVoices({ profileVoices?, lang, profileId, flow })` dans `config.ts` résout la voix finale selon la priorité : override profil non vide > sélection dynamique `selectVoices` (bucket langue, puis EN, puis any) > fallback interne. Les voix globales `mistralVoices`/`mistralVoicesSource` sont legacy, supprimées de `config.json` par `initConfig` ET rejetées avec `logger.warn` dans `saveConfig` (protection client stale entre deux restarts).
- **Liste des voix** (`listVoices`, `generators/tts-provider.ts`) : `client.audio.voices.search` (GET `/v2/audio/voices`, SDK 3) avec `type: 'all'` et `pageSize: 100` (plafond de l'API : 101 → 422, mesuré le 2026-10-24 ; les 68 voix tiennent en une page), curseur `nextPageToken` suivi À LA MAIN : l'itérateur du SDK (`next()`, `for await`) s'arrête dès qu'une page compte moins de `pageSize` voix, même si un curseur suit (catalogue tronqué sans erreur). Garde-fou de 50 pages. La v1 (`voices.list`, pagination par offset) est dépréciée : en-tête `sunset` au 2027-03-31. Verrou : `mistral-client-factory.contract.test.ts` (paramètres envoyés, curseur, `kind`).
- **Drapeau d'une voix** (`langToFlag`, `src/app/config.ts`) : lu dans la langue COMPLÈTE de la voix (`languages[0]` : `en_gb`, `fr_fr`, ou `ar` sans région pour les voix Voxtral 3) ; région si elle est donnée, sinon pays par défaut de la langue (`LANG_DEFAULT_COUNTRY`, drapeaux du sélecteur de langue pour les 9 langues de l'interface). Jusqu'au 2026-10-24, le code de langue passait pour un code pays (ar → Argentine, ca → Canada, hi/ja/ko/zh invalides) et toutes les voix anglaises prenaient le drapeau de la première voix anglaise du catalogue (britanniques en 🇺🇸).
- **Appels `resolveVoices()`** : la signature impose un arg objet avec `lang: string`, `profileId: string | undefined`, `flow: VoiceFlow` (union `'podcast' | 'quiz-vocal' | 'read-aloud'` exportée depuis `types.ts`). Pas de `null` : un seul sentinel "absent" pour les call sites (cf. commentaire `ResolveVoicesArgs` dans `config.ts`). Le typechecker bloque tout call site qui oublie l'un des trois champs. `profileId` seed la **rotation déterministe** par profil (avec `langMatched`, cf. `helpers/voice-selection.ts`) — un même profil garde une identité sonore cohérente à travers les flows. `flow` n'entre **PAS** dans le seed : il existe uniquement pour **contextualiser les logs de fallback** dans `resolveMistralDefaults` (observabilité : savoir quel pipeline a tiré la voix quand on debug).

## Voix et modèle TTS (2026-10-21)

- **Le modèle décide des voix possibles** : `voxtral-mini-tts-2603` (« speech v1 ») refuse en 400 (code 3051, « voice is not supported for speech v1 ») les voix `pvc`, presets Voxtral 3 apparus dans `/v1/audio/voices` le 2026-10-19 vers 19:25 UTC (36 voix : SEULES voix es, pt, it, nl, de, hi, ar ; mêlées aux anciennes en fr et en). La v1.7.11 les choisissait (bucket langue de `selectVoices`) : podcast, quiz vocal, dictée et lecture à voix haute en échec dans 7 langues sur 9 dès le premier rechargement du catalogue (le front le recharge à chaque ouverture). TTS 3 accepte tout, mais n'a qu'une voix native en es, pt, it, nl, de, ar (le podcast y joue les deux rôles avec la même voix).
- **Filtre en quatre points** : `voiceSupportsTtsModel` (`helpers/tts-models.ts`) ; pool de `selectVoices` filtré dans `resolveMistralDefaults` (le cache `setVoiceCache` garde TOUT le catalogue : changer de modèle n'exige aucun appel) ; override `profileVoices` refusé par le modèle → ignoré + `logger.warn` (voix absente du cache → gardée) ; `GET /api/config/voices` filtré par le `ttsModel` configuré, et le front recharge la liste après sauvegarde des Réglages (`reloadMistralVoices`). `resolveVoices` exige `model` (`ttsOptionsFor(...).model`).
- **Compatibilité par `kind` (SDK 3, depuis le 2026-10-24)** : voix speech v1 ⇔ `kind === 'ivc'` (champ de l'API, exposé par le SDK depuis la 3.0 ; toute autre valeur est écartée). Sans `kind`, repli sur le prédicat d'avant le SDK 3 : slug de preset Voxtral 2 `^[a-z]{2}_[a-z]+_[a-z]+$` OU voix personnelle (`custom`, `userId` non nul : clonage instantané, comme la voix d'hôte d'un profil réel) ; `listVoices` journalise alors une fois `N voice(s) without kind`. Prédicat POSITIF : une voix de forme inconnue est écartée (repli sur une autre) plutôt qu'envoyée vers un 400. Verrou : test d'acceptation sur les 68 voix réelles du 2026-10-21 (`helpers/tts-models.test.ts`), avec `kind` puis sans (même verdict voix par voix).
- **Aucun crochet n'est envoyé au TTS** : `textToSpeech` envoie `speakableText(text)` (`helpers/tts-text.ts`) : marqueurs `[Source N]` retirés (2603 les PRONONÇAIT dans la lecture à voix haute des fiches : « Source 2, Source 3 », +2,3 s), autres crochets ôtés en gardant le mot (TTS 3 lit `[…]` comme une balise d'instruction et avale le mot : « Le mot [chat] » → « Le mot »). Regex des marqueurs : source unique `helpers/source-markers.ts`, partagée avec le rendu des pastilles. Les phrases d'une section lue (points clés, vocabulaire, titre et résumé, question et choix du quiz vocal) sont jointes par `joinSentences` (`helpers/tts-text.ts`) : un point seulement entre deux phrases qui n'en finissent pas déjà une (le `join('. ')` d'origine envoyait « …la Terre.. Quand… », relevé le 2026-10-21).
- **Garde-fou Mistral sur le texte (constaté le 2026-10-21, non corrigé)** : la phrase hindie « मुझे लगता है कि वह जूलियस सीज़र है। » (« je pense que c'est Jules César ») est refusée par le TTS à chaque essai (403, code 1920, `guardrail_violation`, catégorie `hate_and_discrimination`), quel que soit le modèle. Classé `content_refused` (message dédié dans les 9 langues) depuis le 2026-10-24, et jamais rejoué par `textToSpeechWithRetry` (la même phrase est refusée à chaque essai) ; avant, il partait en `auth_required` (message de clé API).
