# Cost tracking API

Déplacé tel quel depuis CLAUDE.md (section « Cost tracking API », sauf la règle `tracked-client` restée dans CLAUDE.md), le 2026-10-21.

## Cost tracking API
- **Objectif** : chaque appel Mistral **facturable** (chat, OCR, STT, TTS, agents) est instrumenté pour exposer un coût € estimé à l'utilisateur, persisté par projet. **Exception : la modération** (`client.classifiers.moderate`) n'est PAS wrappée par `tracked-client` — gratuite aujourd'hui (0 $ dans `MODEL_PRICING`) ; le JSON HTTP contient `usage` mais le SDK le retire (`ModerationResponse` sans `usage`, encore vrai en 3.2.0) → si elle redevient payante, l'instrumenter en lisant la réponse brute.
- **Source de vérité pricing** : `helpers/pricing.ts` — `MODEL_PRICING` (par prefix de modèle) + `PRICING_SOURCES` (URL doc Mistral pour scraping tarifaire) + `TOOL_PRICING` (par appel d'outil d'agent, cf. ci-dessous). Prefix matching greedy (plus long gagne, ex: `mistral-large-2512` → `mistral-large`).
- **Frais d'outils des agents** : `TOOL_PRICING` est séparé de `MODEL_PRICING` (unité « appel », pas un préfixe de modèle ; ne PAS en faire une `BillingUnit` : cela casserait les `satisfies Record<BillingUnit,…>` de `cost-calc`, le `never` exhaustif de `src/app/model-pricing.ts` et `scripts/update-pricing.ts`) : `web_search` 0,03 $/appel, `image_generation` 0,10 $/image (mistral.ai/pricing/api, vérifiés le 2026-09-26, **non surveillés** par `update-pricing` → re-vérifier à la main). `wrapAgent` capte `toolCalls` depuis `usage.connectors` (compteur d'appels par outil) s'il reste un compteur valide, sinon en décomptant les sorties `tool.execution` par `name` — jamais les deux ; seuls les entiers finis ≥ 0 sont gardés ; outil sans tarif → `logger.warn` dans `tracked-client`, compté 0 $ (`cost-calc` reste pur). `connectorTokens` (`usage.connector_tokens`) est HORS `prompt_tokens` (mesuré : total = prompt + completion + connector) → compté au tarif d'entrée du modèle de l'agent (estimation prudente). `calculateCost` = coût modèle + Σ `perCall` × n (frais d'outil dus même sans tarif modèle) ; `aggregateUsage` fusionne `toolCalls` et `connectorTokens` ; `buildCostBreakdown` ajoute `N × outil × $X/call` et `N tool tokens in`. **Limite connue** : `conversations.start` est rejoué par le backoff du SDK (429, 500, 502, 503, 504), puis par `callWithRetry('agent')` sur les transitoires que le SDK ignore (408, autres 5xx dont 52x), et seule la réponse finale porte un `usage` → les frais d'outils d'une tentative échouée (ex. une image générée, 0,10 $, avant un 5xx) ne sont pas captés, et une image peut être facturée deux fois.
- **OCR 3/OCR 4 + medium** : `MODEL_PRICING` distingue `mistral-ocr-4` ($4/1000 pages : OCR 4.1 `mistral-ocr-4-1`, défaut, et l'ancien OCR 4.0 `mistral-ocr-4-0`, retiré le 2026-09-30, même `billing_model_name`) de `mistral-ocr` ($2/1000, OCR 3 `mistral-ocr-2512`) — le greedy-prefix (plus long gagne) résout le tarif sur l'**id capturé** par `tracked-client`, qui n'est PAS forcément daté (mesuré 2026-09-25) : chat/OCR/STT → `response.model` = l'id **demandé tel quel, alias compris** ; TTS → `request.model` ; agents → `mistral-large-latest` forcé ; seule `/v1/moderations` renvoie l'id résolu daté. **Conséquence** : un alias repointé vers une version d'un autre prix garderait l'ancien tarif en silence (ex. `mistral-ocr-latest` sert OCR 4.1 mais tomberait sur le préfixe `mistral-ocr` = tarif OCR 3 — d'où son rejet par `normalizeOcrModel`) → envoyer un id versionné dès que le prix varie dans une famille, avec une clé `MODEL_PRICING` distincte. `mistral-medium` ($1.5/$7.5 /M tokens) ajouté. **Tarifs affichés dans les sélecteurs Réglages** via `src/app/model-pricing.ts` (`modelPriceLabel` dérive de `MODEL_PRICING`, seul le suffixe d'unité est traduit → zéro duplication de prix dans l'i18n ; `toFixed(2)` sur tokens).
- **Mistral Large 4 en option** (`MISTRAL_LARGE_4 = 'mistral-large-4-0'`, `helpers/chat-models.ts`, sélecteur « Génération » des Réglages ; Large 3, `mistral-large-latest`, reste le défaut recommandé) : tarif public de 1,36 $ / 4,18 $ par M tokens (×2,7 et ×2,8 par rapport à Large 3) sous sa propre clé `mistral-large-4` ; la promotion de lancement (-50 % pendant 2 semaines à partir du 2026-10-06, sans date de fin publiée) n'est pas reportée, le coût affiché est donc surestimé jusqu'à sa fin. `update-pricing` lit aussi une ligne de prix en promotion (tarif public barré en tête). **Large 4 raisonne par défaut**, contrairement à Large 3, Medium 3.5 et Small 4 : mesuré le 2026-10-08 sur 3 questions de quiz, 907 tokens de sortie en 30 s (réponse `[thinking, text]`), contre 123 en 2,7 s avec `reasoningEffort: 'none'`. `withReasoningDefault`, appliqué par `wrapChatComplete` (`tracked-client`) à toute requête de chat, envoie donc `reasoningEffort: 'none'` aux familles de `REASONING_BY_DEFAULT` quand l'appelant ne choisit rien. Qualité non mesurée sur nos générations : la mesurer (protocole OCR : critères écrits AVANT, vraies leçons, plusieurs passages) avant d'en faire le défaut.
- **Chaîne de calcul** : `helpers/tracked-client.ts` wrappe le client Mistral (capture `ApiUsage`) → `helpers/usage-context.ts` (AsyncLocalStorage pour propager l'usage dans les pipelines async) → `helpers/cost-calc.ts` (conversion usage → € selon l'unité : `tokens` / `characters` / `pages` / `audio-seconds`, + frais par appel des outils d'agents) → `helpers/cost-persist.ts` (écriture dans `Project.costLog` + mise à jour `totalCost`) → `helpers/cost-middleware.ts` (injection du `costDelta` dans la réponse HTTP). **Modèle sans tarif** (`resolvePricing` nul) : compté 0 $, et `persistUsage` n'écrit rien pour un coût nul → `tracked-client` émet `logger.warn('cost', 'model without pricing: <id> ($0)')` à chaque capture (même régime qu'un outil d'agent sans tarif) ; ajouter l'id à `MODEL_PRICING`. Un tarif explicite à 0 $ ne déclenche rien.
- **Contrat endpoint** : les réponses `/generate/*` et `/sources/*` décorent l'objet retourné (Generation ou Source) avec `estimatedCost: number`, `usage: GenerationUsage`, `costBreakdown: string[]`. Parmi les `/generate/*`, **seul** `POST /generate/route` renvoie un champ top-level `costDelta: number` (coût du routage seul) — les autres exposent leur coût via `gen.estimatedCost` uniquement. Hors `/generate/*`, un `costDelta` top-level (coût de CET appel, que le front ajoute au total du projet via `addCostDelta`) est renvoyé par le chat (`{ reply, …, costDelta? }`), la lecture à voix haute (`{ audioUrl, costDelta? }`), **`POST /:pid/detect-consigne` → `{ consigne, costDelta }`** (`consigne` = consigne persistée ou `null`, `costDelta` toujours un nombre, 0 sans usage facturable ; libellé costLog `…/detect-consigne` → « Détection de consigne », détection de fond comprise) et **`POST /:pid/generations/:gid/vocal-answer`** → `{ correct, feedback, transcription, costDelta? }` ou, sur un refus, `{ error, costDelta? }` (STT + vérification ; présent dès que non nul, refus compris : la transcription est facturée ; libellé `…/vocal-answer` → « Réponse vocale »). `GET /projects/:pid` retourne le projet enrichi de `totalCost` (somme calculée depuis `costLog[]`) + `costLog[]` historique.
- **Test de contrat du SDK** (`helpers/mistral-client-factory.contract.test.ts`, à faire passer à chaque bump de `@mistralai/mistralai`) : VRAIE instance construite par `buildTrackedClient`, seul `fetch` est stubbé (le `DEFAULT_FETCHER` du SDK le lit à chaque appel) → vérifie que les accesseurs de sous-clients restent mis en cache (`client.chat === client.chat` : condition du remplacement des méthodes par `tracked-client`) et que `runWithUsageTracking` capte l'usage de chat, STT, OCR, TTS et agents (réponses agents `web_search` / `image_generation` capturées en réel). `tracked-client.test.ts`, lui, tourne sur un faux client et ne voit pas une régression du SDK.

- **Voxtral 3 (2026-10-21)** : clés `voxtral-mini-tts-3` (13 $/M caractères), `voxtral-mini-transcribe-3` (0,0035 $/min) et `voxtral-small-transcribe-3` (0,004 $/min), plus longues que `voxtral-mini-tts` / `voxtral-mini` : elles gagnent le greedy-prefix pour l'id `-3-0` comme pour son alias `-3`. Prix STT écrits par minute (`perMinute`, comme sur les fiches) et affichés par minute dans le sélecteur « Transcription » (`usdPerMinute`, 4 décimales, clé i18n `settings.perMinute`, comme la ligne de coût de `cost-calc`). Sans ces clés, TTS 3 était compté 16 $, Mini Transcribe 3 0,003 $/min et Small Transcribe 3 0 $ avec un warn à chaque appel. `prompt_audio_seconds` est un ENTIER tronqué par l'API (17,88 s → 17) : le coût STT affiché est légèrement sous-estimé. Contrôle : `npx tsx scripts/update-pricing.ts voxtral` (5 fiches conformes le 2026-10-21).
